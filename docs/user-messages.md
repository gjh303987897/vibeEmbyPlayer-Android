# 用户消息与错误提示

Android 端的页面不直接把异常对象或网络库的原始文本交给用户。所有需要展示的错误都由 `UserMessageFormatter` 归类为网络、认证、权限、找不到资源、超时、输入、请求拒绝、服务端或格式错误，再由 `AppMessageCard`、`AppInlineError` 或 `AppSnackbarHost` 使用 Material 3 样式呈现。

## 展示规则

- 会阻止页面继续使用的错误显示为带图标的消息卡片，并提供“重试”；列表已有内容时，错误卡片显示在列表顶部。
- 保存、上传、创建目录、导入和备份等结果使用带颜色和图标的 Snackbar 区分成功、警告和失败。
- 输入校验使用紧邻输入框的内联提示；播放错误使用播放器覆盖层中的可读说明。
- 未知错误只保留短文本，过滤换行、堆栈信息、过长内容，并遮盖 URL 中的用户名、密码和 token。

## 开发约定

新增页面应保存结构化状态（错误文本、消息类型和必要的重试动作），不要在 Compose 中直接读取 `Throwable.message`。新文案应同时加入 `values/strings.xml` 和 `values-zh/strings.xml`；技术细节应记录到日志而不是展示给用户。
